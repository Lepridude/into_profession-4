# Развёртывание Flask-приложения в Amvera Cloud

Основной исходный код находится в GitHub:  
https://github.com/Lepridude/into_profession-4

## Конфигурация

В корне проекта находится `amvera.yml`:

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: "3.11"

run:
  command: "gunicorn --bind 0.0.0.0:${PORT:-8000} app:app"
  containerPort: 8000
```

Команда запускает Flask через Gunicorn. Порт читается из `PORT`, а значение по умолчанию — 8000.

## Подключение GitHub

1. В Amvera создайте приложение Python или откройте уже созданное.
2. Откройте вкладку **Репозиторий** и выберите подключение внешнего Git-сервиса.
3. Выберите **GitHub**, событие **Push** и ветку `main`.
4. Скопируйте предложенные Amvera **Payload URL** и секрет вебхука. Не публикуйте их.
5. В GitHub откройте `Lepridude/into_profession-4` → **Settings** → **Webhooks** → **Add webhook**.
6. Вставьте Payload URL, укажите Content type `application/json`, добавьте секрет, выберите событие **Just the push event** и сохраните webhook.
7. Вернитесь в Amvera и нажмите **Применить**, если этого требует интерфейс.

Для подключения GitHub Amvera просит токен и для публичного, и для приватного репозитория. Создайте fine-grained token и выдайте только разрешения, которые показаны в интерфейсе Amvera. Не публикуйте токен и храните его только в настройках интеграции. Официальная инструкция: https://docs.amvera.ru/applications/git/webhooks.html

После успешной привязки push в `main` должен запускать обновление проекта. Следите за статусом сборки и логами в панели Amvera.

## Переменные и секреты

Добавьте в разделе **Переменные и секреты**:

| Переменная | Значение |
|---|---|
| `LOGINOM_URL` | Полный URL опубликованного Loginom `GetUserHistory` |
| `LOGINOM_CHECK_URL` | Полный URL отдельного `CheckUserId`; пока метод не опубликован — пустая строка |
| `LOGINOM_TIMEOUT` | `45` |
| `GIGA_MODEL` | `GigaChat-2` |
| `GIGA_KEY` | Секрет: действующий ключ GigaChat |
| `SECRET_KEY` | Секрет: длинная случайная строка Flask |
| `COOKIE_SECURE` | `1` для HTTPS-домена |
| `FLASK_DEBUG` | `0` |
| `PORT` | Обычно задаётся платформой; конфигурация использует 8000 по умолчанию |

Не загружайте локальный `.env` в GitHub и не добавляйте его как обычный файл проекта. Ключи и токены вводятся в настройках Amvera как секреты.

## Домен и проверка

1. Вкладка **Домены** → создайте внешний домен.
2. Выполните сборку и запуск.
3. Откройте `https://ВАШ-ДОМЕН/health`. Ожидаемый ответ — JSON со статусом `ok`.
4. Введите существующий `user_id`, войдите и запустите анализ.
5. Проверьте отказ для несуществующего ID и результат GigaChat.
6. Проверьте логи приложения, если сервис не запускается.

Перед сдачей 17 декабря 2026 года убедитесь, что приложение снова запущено и доступно по домену. В остальное время его можно остановить для экономии баланса.

## Текущий статус

Файлы для облачного запуска готовы, а GitHub Actions проверяет Python-код. Само приложение в Amvera нельзя считать развёрнутым, пока в личном кабинете не привязан GitHub, не заданы секреты, не создан домен и не пройдена проверка `/health`. Публикация персонального `CheckUserId` и реальный запрос GigaChat также остаются отдельными внешними шагами.
