# Loginom 7.3.1 — настройка двух REST-сервисов

В исходном пакете `instacart_ws_fio.lgp` из ZIP материалов занятия уже есть SQLite-подключение и импорты `orders`, `orders_prior`, `products`. Сам файл находится в приложенном к проекту ZIP-архиве; извлеките его в папку `loginom/` перед открытием в Loginom. Внутреннее имя пакета в исходном XML — `instacart_ws_fio1`. Сами методы `GetUserHistory` и `CheckUserId` в исходном пакете ещё не созданы. База `instacart_db.sqlite` (~2,2 ГБ) в архив не вложена.

## Подготовка пакета
1. Откройте `loginom/instacart_ws_fio.lgp` в Loginom 7.3.1.
2. Сохраните копию под именем `АрхангельскийДанила_Instacart.lgp`.
3. Скачайте БД по ссылке из файла занятия `База данных Instacart на SQLLite (ссылка на скачивание).txt`.
4. В подключении `Instacart` укажите фактический путь к `instacart_db.sqlite`.
5. Проверьте доступность таблиц `orders`, `orders_prior`, `products`.

## Сервис GetUserHistory
1. Создайте модуль `GetUserHistory`, добавьте ссылку на подключение `Instacart` и узел «База данных».
2. Создайте входную переменную `user_id` типа Integer.
3. В SQL-узел вставьте первый запрос из `queries.sql`, передав `:user_id` из входной переменной.
4. Проверьте результат для `user_id=1`. Методичка указывает, что до фильтра в примере было 18 строк.
5. Добавьте «Фильтр строк» и оставьте первые 10 строк.
6. Сверните сценарий в подмодель `GetUserHistory`, настройте входной порт переменных и выходной порт таблицы, свяжите входную переменную с SQL-узлом.
7. Опубликуйте подмодель с именем `GetUserHistory`.

Ожидаемый REST-запрос: `{"Variables":{"user_id":1}}`. Ожидаемый результат: `DataSet.Rows` с полями `product_name`, `department_rus`, `aisle`, `order_count`.

## Сервис CheckUserId
1. В том же пакете создайте отдельный модуль `CheckUserId`.
2. Добавьте ссылку на подключение `Instacart` и узел «База данных».
3. Создайте входную переменную `user_id` типа Integer.
4. Вставьте второй SQL-запрос из `queries.sql`.
5. Убедитесь, что выход — ровно одна строка с полем `user_exists`: 1, если в `orders` есть такой пользователь, иначе 0.
6. Сверните сценарий в подмодель, настройте входной порт переменных и выходной порт таблицы, свяжите переменную с SQL-узлом.
7. Опубликуйте подмодель с точным именем `CheckUserId`.

## Публикация на edu.loginom.dev
1. Откройте `https://edu.loginom.dev/app/` и войдите с учётными данными сервера РЭУ.
2. Перенесите пакет на сервер и перенастройте путь к БД так, чтобы файл был доступен серверу.
3. В разделе «Веб-сервисы» выберите «Добавить» → «Генерировать уникальное имя пакета» → «Опубликовать».
4. Откройте `https://edu.loginom.dev/lgi/rest/help`, найдите опубликованный пакет и скопируйте полные URL обоих методов.
5. Проверьте POST-запросы для существующего и несуществующего ID.
6. Запишите выданные URL в корневой `.env`:

```dotenv
LOGINOM_URL=https://edu.loginom.dev/lgi/rest/УНИКАЛЬНОЕ_ИМЯ/GetUserHistory
LOGINOM_CHECK_URL=https://edu.loginom.dev/lgi/rest/УНИКАЛЬНОЕ_ИМЯ/CheckUserId
```

Не угадывайте уникальное имя пакета. Используйте то, которое фактически показано в `/lgi/rest/help`.

## Проверка контракта
- `CheckUserId`: `DataSet.Rows[0].user_exists` равен 1/0.
- `GetUserHistory`: `DataSet.Rows` содержит не более 10 строк и четыре поля, которые читает Flask.
- Если фактический JSON отличается, скорректируйте парсер в Python по реальной схеме REST API.

**Текущее ограничение:** исходный LGP ещё не содержит эти модули и не опубликован. Создание/публикация требует доступа к Loginom и базы Instacart объёмом ~2,2 ГБ.
